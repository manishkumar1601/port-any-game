# M2a: upstream-runtime lanes (EasyRPG, LÖVE, Ren'Py): design

**Status:** approved by the owner by delegation (18-11-2026: "go as per your decisions"). Parent design: [2026-11-17-port-any-game-design.md](2026-11-17-port-any-game-design.md) (§6 lane catalog, §16 roadmap). Evidence: spikes [f-easyrpg-web](../../spikes/f-easyrpg-web.md), [g-lovejs](../../spikes/g-lovejs.md), [h-renpy-web](../../spikes/h-renpy-web.md).

## 1. Intent

M2 ("Runtimes and Remote Play") is split into four parts, done in this order (owner's call, 18-11-2026):

1. **M2a, this design:** lanes whose web runtime is published upstream and can be pinned: `rt-easyrpg`, `rebuild-love`, `rebuild-renpy`.
2. M2b: `remote-play`.
3. M2c: runtimes we build in our own CI (`rt-scummvm`, `rt-idtech`), which needs a release-publishing decision from the owner.
4. M2d: catalog expansion (PortMaster, libretro subset).

The owner wants every type of game supported, released as open source. M2a adds three game families (RPG Maker 2000/2003, LÖVE, Ren'Py) using the M1 lane pattern, with no new infrastructure.

## 2. Goals, non-goals, anti-goals

**Goals**
- The three lanes are `available: true`. Survey ranks them and `pag new`/`build`/`pack`/`verify` work end to end.
- Each runtime is pinned in `toolchain.lock.json` (URL, size, SHA-256, licence, source) and installed by `pag setup <name> --yes`.
- Each lane has a fixture we author (MIT, generated by a `test/fixtures/make-*.mjs` script) that passes `pag verify` in the lane e2e on Windows, macOS and Ubuntu CI.
- Each lane has an agent runbook in `references/lanes/`, and the system docs are updated.

**Non-goals (later or backlog)**
- Ren'Py 7.x (second SDK pin), 6.x, BYO Ren'Py.
- LÖVE 11.5-only and 12.x features (needs a newer love.js), LuaJIT/`ffi`.
- Automatic RTP merging for RPG Maker 2000/2003; user-supplied SoundFonts.
- Exporting and importing saves through the shell UI (still backlog).

**Anti-goals**
- Game data, game-data URLs or third-party game assets in the repo. EasyRPG's TestGame (GPL-3.0 with CC-BY assets) and any shipped Ren'Py or LÖVE game stay out.
- GPL code vendored into the repo. EasyRPG (GPL-3.0) is downloaded by `pag setup`, kept in its own folder, unmodified, with its licence text and a source offer in every dist.
- Decompiling Ren'Py scripts (`unrpyc`) or rewriting a game's code.

## 3. Constraints

All of the parent design's constraints hold: Node ≥ 20.12, zero runtime dependencies, ESM `.mjs`, cross-OS paths; scripts are authoritative and hooks fail open; BYO is the default data mode and bundled builds are private unless the rights-holder gate passes; a DRM'd executable means STOP. The page CSP is the base policy in `pack.mjs`; a lane may add only quoted keywords.

## 4. Approaches considered

| Decision | Options | Chosen | Why |
|---|---|---|---|
| LÖVE data mode | (a) bundled: love.js CLI output in `build/game`, web-extract iframe (parent spec); (b) BYO: adapter writes the user's `.love` into the Emscripten FS | **(b) BYO** | Spike g observed it working under the base CSP. Game data never enters `dist`, so the page can live on any static host. No love.js CLI or npm dependencies. |
| EasyRPG file loading | (a) HTTP from `game/` (bundled only); (b) service worker; (c) XHR shim serving `ctx.files.read()` | **(c) XHR shim** | Spike f observed it working for BYO and bundled alike. `connect-src 'self'` blocks `blob:` fetches, and the shell has no service worker. |
| Ren'Py data mode | (a) bundled: SDK `web_build` output, web-extract iframe; (b) BYO: patch `fetch('game.zip')` with a zip built from OPFS | **(a) bundled** | Observed working in spike h. BYO is unverified and needs a patched `fetch`; it goes to the backlog. |
| Frames for Ren'Py | (a) Ren'Py-only frame hook; (b) shared frame hook gains a WebGL draw-call fallback | **(b)** | Ren'Py never calls `requestAnimationFrame`. Other timer-driven web games (web-extract) gain the same fallback. |
| Ren'Py runtime licence ack | with or without `ACK_RUNTIME_LICENSE` | **with** | LGPL parts are linked into `renpy.wasm`, and every other runtime lane asks for it. |

## 5. Shared changes

1. **`setup` (lock and extraction)**
   - `extractZip` gains `{strip}` like `extractTarGz` (the Ren'Py SDK zip has a `renpy-8.6.1-sdk/` prefix).
   - A lock entry may list `extras: [{url, sha256, size, archive, strip, into}]`. Each extra is downloaded and checked like the main archive, then extracted into `<toolDir>/<into>` before `.ok` is written. Ren'Py's web zip is an extra with `into: "web"`. EasyRPG's `COPYING` is an extra with `archive: "file"` (a single file copied as is).
   - `pag setup` gains aliases: `easyrpg`, `love`, `renpy`. The usage line and the size message list them, and the Ren'Py message says "about 180 MB download, about 400 MB on disk".
   - The zip extractor must keep executable bits (it already does from the external attributes). Symlink entries in the Ren'Py SDK zip must be checked: handle them, or prove there are none.
2. **Licences in `pack`.** GPL-3.0 runtimes get the same treatment as GPL-2.0: the licence text goes into `LICENSES/<tool>.txt` with the source-offer line. The text comes from the tool's `licenseFile` (EasyRPG's pinned `COPYING` extra), so no GPL-3.0 copy is vendored unless the extra cannot be pinned.
3. **`pack` refuses a BYO lane that has a build step but no `build/lane.json`** ("run pag build first"). This closes the M1 backlog item L for `rt-ruffle` and `dos-jsdos` and covers the two new BYO lanes.
4. **Frame hook.** `assets/lanes/web-extract/frame-hook.js` counts one frame per task that issues a WebGL draw call (`drawArrays`/`drawElements` on WebGL1/2 contexts), but only while no `requestAnimationFrame` frame has been seen. Pages that use rAF behave exactly as today.
5. **Web-build helper.** web-extract's "normalise the entry, inject the hook, swap the temp folder in" step is exported once and reused by `rebuild-renpy`. The adapter is reused through the lane `adapter` field.
6. **Survey.** `engines.json` gains a `version` extractor for `renpy` (`renpy/vc_version.py`, then `game/script_version.txt`). The love and RPG Maker 2000/2003 versions are read by the lane build steps, not the survey (they live inside a zip or an exe).
7. **Stubs.** The three lanes leave `stubs.mjs` and register in `lanes/index.mjs`. No new ack ids: the lanes use `ACK_PRIVATE_USE_ONLY` and `ACK_RUNTIME_LICENSE`.

## 6. Lane designs

### 6.1 `rt-easyrpg` (rung 1, BYO)

- **Detect:** engine `rpgmaker-2k` gives GO.
- **Runtime:** `easyrpg-player-js` 0.8.1.1, `https://easyrpg.org/downloads/player/0.8.1.1/easyrpg-player-0.8.1.1-js.tar.gz`, `tgz`, `strip: 1`, size and SHA-256 from spike f. Licence `GPL-3.0-or-later`, with `COPYING` pinned as an extra from the 0.8.1.1 tag. Source `https://github.com/EasyRPG/Player`. `runtime.files`: `index.js`, `index.wasm`.
- **Build:** writes `build/lane.json` `{root, engine, encoding, rtp}`.
  - `root`: the folder that holds `RPG_RT.ldb`.
  - `engine`: from `RPG_RT.exe` when it can be identified read-only, else omitted (the player then guesses from the database).
  - `encoding`: `RPG_RT.ini [EasyRPG] Encoding` when present, else omitted (ICU guesses).
  - `rtp`: `full-package` when `RPG_RT.ini` has `FullPackageFlag=1`, else `needs-rtp`. `needs-rtp` makes the build verdict HARD, not NO: the game still runs, and missing RTP graphics are drawn as a checkerboard. The fix path in the log and the runbook, as RPG Maker's own "full package" export does it:
    1. copy the game folder;
    2. merge the user's own RTP into the copy;
    3. set `FullPackageFlag=1` in the copy's `RPG_RT.ini`;
    4. run `pag new` on the copy.
- **Adapter:**
  1. Create `<canvas id="canvas" tabindex="-1">` in `ctx.host` and focus it.
  2. Replace `window.XMLHttpRequest` with a shim. It answers `games/<id>/index.json` with a generated gencache v2 index (format in spike f) and every other `games/<id>/<path>` from `ctx.files.read()`.
  3. Load `index.js` and call `createEasyRpgPlayer({game, onRuntimeInitialized, preMainLoop, postMainLoop, setStatus: noop})`, passing the arguments `--engine`/`--encoding` from `lane_config`. The player must not write into the shell's `#status`.
  4. `postMainLoop` calls `ctx.reportFrame()`. `preMainLoop` returns false while paused.
  5. `saveNow()` forces `FS.syncfs(false)` and resolves when it completes.
- **Shell:** `csp: {'script-src': ["'unsafe-eval'"]}` (required, observed). `verify: {inputs: ['Enter'], target_fps: 30, budget_ready_s: 30}`.
- **Fixture:** `make-rm2k.mjs` writes our own `RPG_RT.ldb`, `RPG_RT.lmt`, `RPG_RT.ini` (`FullPackageFlag=1`) and an 8-bit palette `Title/Title.png`, all under 2 KB.
- **Known gaps** (runbook): no RTP and no exe reading on the web; Maniac Patch partial; DynRPG mostly unsupported; MIDI quality without a SoundFont.

### 6.2 `rebuild-love` (rung 3, BYO)

- **Detect:** engine `love` gives GO. The real verdict comes from `build`, as with web-extract (R38).
- **Runtime:** npm `love.js` 11.4.1 (LÖVE 11.4), tarball URL, size and SHA-256 from spike g, `tgz`, `strip: 1`, MIT, `licenseFile: LICENSE`. `runtime.files`: `src/compat/love.js`, `src/compat/love.wasm`. Use the compat build only: the threaded build crashes without COOP/COEP.
- **Build:** finds the game container and writes `build/lane.json` `{file, offset, version, identity}`. No derived game file is written, so the data stays BYO.
  - **Container:** a plain `.love` file (`offset: 0`); a fused exe (`offset` = the zip start found with `listZip`, `min(entry.offset)`); or a macOS `.app/Contents/Resources/*.love`.
  - The zip must have `main.lua` at its root. A wrapper folder is a clear build error.
  - **Verdict** from `conf.lua` `t.version`:
    - 11.0–11.4: GO;
    - 11.5: GO with a warning;
    - 0.x or 10.x: HARD;
    - 12.x: NO;
    - unknown: HARD.
  - Native modules (`.dll`/`.so`/`.dylib` in the zip, `require("ffi")`, `package.loadlib`) give NO.
- **Adapter** (in the shell page, like Ruffle):
  1. Create a focusable canvas.
  2. Read the file from `ctx.files.read(file)` and slice it at `offset`.
  3. Set `window.alert` to a function that reports a warning instead of blocking, while love starts.
  4. Load `love.js` and call `Love(Module)` with `arguments: ['./game.love']`, `INITIAL_MEMORY` 16 MiB, `canvas`, `locateFile` into the runtime folder, and a `preRun` that writes `/game.love` with `FS_createDataFile`.
  5. Count frames from the Emscripten rAF loop.
  6. `saveNow()` dispatches a synthetic `beforeunload`, which is love.js's only IDBFS write-back. It runs on a timer, on `pause()` and on `pagehide`.
  7. A Lua error screen still paints frames, so the adapter watches love's `printErr`/`print` for `Error` and `stack traceback` and reports an error.
- **Shell:** no CSP relaxation and `needs_coi: false`. `verify: {inputs: ['Click', 'Enter', 'Space'], target_fps: 30}`.
- **Fixture:** `make-love.mjs` writes our own `main.lua` and `conf.lua` (a colour cycle, a key counter, a run counter in `love.filesystem`), zipped into `.love`. It also writes a fused variant (an own-bytes stand-in exe plus a placeholder `love.dll` plus the zip) and an `old` variant (`t.version = "0.10.2"`).

### 6.3 `rebuild-renpy` (rung 3, bundled)

- **Detect** (survey version):
  - 8.x at or below the pinned SDK: GO.
  - Unknown version: HARD, re-checked by `build`.
  - 7.x, 6.x, or 8.x newer than the pin: HARD, with the reason ("needs Ren'Py 7 SDK, not pinned yet").
- **Runtime:** tool `renpy` 8.6.1. The main archive is `https://www.renpy.org/dl/8.6.1/renpy-8.6.1-sdk.zip` (`strip: 1`), with the extra `renpy-8.6.1-web.zip` extracted into `web/`. Sizes and SHA-256 come from spike h and match upstream `checksums.txt`. Licence `MIT AND LGPL-2.1-or-later`, `licenseFile: LICENSE.txt`.
  - `runtime` is `{tool: 'renpy', files: []}`. The web runtime travels inside the build output.
  - `files: []` matters. Without a `files` list, `pack` copies the whole SDK folder into `dist/runtime`. Without a `runtime` at all, no Ren'Py licence goes into `LICENSES/`.
- **Build:**
  1. Copy only the game's `game/` into `build/renpy-project/game/`.
  2. Run `<sdk>/lib/py3-<os>-<arch>/python[.exe] <sdk>/renpy.py <sdk>/launcher web_build build/renpy-project --destination <tmp>`, with `SDL_VIDEODRIVER=dummy` and `SDL_AUDIODRIVER=dummy`, plus a timeout.
  3. Remove the sibling zip, `*.symbols`, the PWA files and the service-worker registration.
  4. Run the shared web-build helper (hook injection, swap into `build/game`).
  5. Write `build/lane.json` `{game_version, sdk_version}`.
  6. Fail clearly on "Web support is not available". Warn when `config.save_directory` is missing, because saves would then not persist.
- **Pack and shell:**
  - `requiresBuild: true`; the adapter is web-extract's.
  - `csp: {'script-src': ["'unsafe-eval'", "'unsafe-inline'"]}` (both required, observed) and `needs_coi: false`.
  - `verify: {inputs: ['ArrowDown', 'Enter', 'Click', 'Enter'], target_fps: 5, budget_ready_s: 30}`.
- **Data mode and acks:** `bundled`, with `ACK_PRIVATE_USE_ONLY` and `ACK_RUNTIME_LICENSE`.
- **Fixture:** `test/fixtures/renpy-tiny/` is our own `game/script.rpy` and `game/options.rpy` (with `config.save_directory`), plus our own `renpy/vc_version.py` stub naming 8.6.1, so detection runs. The SDK compiles `.rpy` during the build.

## 7. Testing and CI

- **Unit tests**, one file per lane under `test/lanes/`, cover:
  - `detect` verdicts;
  - the build steps on generated fixtures: container finding, zip slicing, version rules, `lane.json`;
  - adapter helpers exported for Node: the gencache index builder, the love container offset;
  - the setup `extras` and zip `strip` paths, with a local HTTP server as in the M1 setup tests;
  - pack's licence output for GPL-3.0;
  - the pack refusal;
  - the frame-hook fallback, in the Node-side tests where possible.
- **Lane e2e** (`npm run e2e`): for each fixture, `setup`, `new`, `build`, `pack`, then `verify` with frames, input and save checks. It runs on the three CI operating systems.
- **CI:** caches the tool folder keyed by the lock file's hash, because Ren'Py alone is 177 MB. Ubuntu runs the Ren'Py build with the dummy SDL drivers.
- **e2e fps override:** `PAG_E2E_TARGET_FPS` (macOS CI) may only lower a lane's `target_fps`, never raise it. `test/e2e/run.mjs` applies `min(override, lane target)`, so Ren'Py stays at 5.
- **Exit criteria for M2a:**
  - the three fixtures pass verify on Windows, macOS and Ubuntu CI. The one allowed exception is the Ren'Py SDK failing to build headless on an OS after one bounded fix attempt. Then the build step reports HARD with the reason on that OS, and the e2e asserts that exact reason there instead of skipping;
  - the unit suite is green;
  - survey on each fixture names the new lane as primary;
  - docs and runbooks are updated.

## 8. Risks

- **Not yet run on macOS or Linux** (all three spikes were Windows/Edge only). Possible problems: Gatekeeper, missing SDL libraries, exec bits, symlinks in the SDK zip. CI on three operating systems catches these. If it fails, Ren'Py on that OS becomes HARD with the reason given, not a skipped test.
- **love.js has a single maintainer, and the 11.5 build is untagged.** Pin 11.4.1; the upgrade path (2dengine) is noted in the runbook.
- **Ren'Py frame rate is about 10 fps when idle.** `target_fps: 5` stays a lane setting; the product thresholds for other lanes are unchanged.
- **Big Ren'Py games** download all their `.rpa` files before the title screen. The runbook warns, and verify's `budget_ready_s` can be raised per port.

## 9. Calls made after the builder check (owner: please check)

These are recorded in `docs/decisions.md` when they land.

1. **Third-party notices inside runtime wasm files.** The EasyRPG and love.js wasm files statically link SDL2, ICU, FreeType, Lua and others. The M1 runtimes (Ruffle, js-dos) have the same gap. M2a ships each tool's own licence and the GPL source offer. A complete, verified per-library notice set for every runtime becomes a **[1.0]** backlog item, together with M14. Reason: dists are private by default, the release gate is still open, and copyright lines must come from verified upstream text, not from memory.
2. **The Ren'Py build runs the game's own startup code on the host.** `web_build` executes the game's init Python once, as launching the game would. The user owns and already runs this game, and DRM still means STOP before any build. So there is no new ack. The fact goes into `safety-and-policy.md`, the Ren'Py runbook and the decision log.
3. **Ren'Py on macOS or Linux CI.** One bounded fix attempt per OS. After that, the build reports HARD with the reason on that OS, and the e2e pins that reason (see §7). This verdict comes from the build step; `detect` stays pure.
4. **RTP stays HARD until the user's copy is a full package** (see §6.1). Reading asset references out of LCF data to detect a merged RTP is deferred.

## 10. Left to the builder

- Exact verify inputs and timings beyond those above. Tune them against the fixtures in CI.
- How `RPG_RT.exe` maps to an EasyRPG `--engine` value (PE version resource or size table). If neither can be identified read-only, leave `engine` unset.
- Whether the WebGL fallback counts per task or per microtask batch. Count per task, as spike h did, unless the tests show a reason to change.
- Wording of runbooks and log lines.
